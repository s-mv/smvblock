# smvblock Protocol

This document defines the communication protocol used in smvblock between:

-   Python client (task generator + gRPC client)
-   Rust nodes (execution + routing peers)

The system is a decentralized compute mesh where tasks are propagated and
executed based on local capacity.

--------------------------------------------------------------------------------

# 1. Core Concept

A **task** is the atomic unit of computation.

Tasks are:

-   generated by PyTorch FX lowering
-   sent to a node via gRPC
-   executed locally or forwarded to peers
-   eventually resolved into a result

There is no global scheduler.

--------------------------------------------------------------------------------

# 2. Transport Layer

All communication uses:

-   gRPC (primary transport)
-   Protocol Buffers (serialization)
-   Rust tonic (node implementation)
-   Python grpcio (client)

--------------------------------------------------------------------------------

# 3. gRPC Service Definition

Each node exposes:

    service SmvNode {
      rpc Execute(Task) returns (TaskResult);
      rpc Forward(Task) returns (TaskResult);
    }

--------------------------------------------------------------------------------

# 4. Task Format (Protobuf equivalent)

    message Task {
      string id = 1;
      string op = 2;
      string inputs = 3;
      int32 ttl = 4;
    }

--------------------------------------------------------------------------------

## 4.1 Fields

### id

Unique task identifier.

--------------------------------------------------------------------------------

### op

Primitive operation type.

Supported: - matmul - add - sub (future)

--------------------------------------------------------------------------------

### inputs

Serialized input payload.

Note: - MVP uses string serialization - future versions will use typed tensor
messages

--------------------------------------------------------------------------------

### ttl

Limits propagation depth.

Rules:

-   decremented per hop
-   if ttl == 0 then just drop the task

--------------------------------------------------------------------------------

# 5. Task Result

    message TaskResult {
      string id = 1;
      string status = 2;   // ok | forwarded | dropped
      string result = 3;
    }

--------------------------------------------------------------------------------

# 6. Node Behavior Model

Each node is symmetric.

## Step 1: Receive Task

Via gRPC Execute()

--------------------------------------------------------------------------------

## Step 2: Capacity Check

Each node maintains:

    capacity: int
    current_load: int

If:

    current_load < capacity

→ execute locally

Else: → forward to peer

--------------------------------------------------------------------------------

## Step 3: Execution

Execution backend: - Rust GPU runtime (PyTorch C++ bindings or modular backend)

Returns:

    TaskResult {
      id,
      status = "ok",
      result
    }

--------------------------------------------------------------------------------

## Step 4: Forwarding

If overloaded: - decrement ttl - send via Forward RPC - choose peer node

--------------------------------------------------------------------------------

# 7. Client Protocol

## attach

    client.attach("localhost:7000")

Creates gRPC channel to entry node.

--------------------------------------------------------------------------------

## deploy

Pipeline:

    PyTorch model
        to
    FX tracing
        to
    lower.py (IR tasks)
        to
    gRPC Execute()

--------------------------------------------------------------------------------

## detach

Closes gRPC channel.

--------------------------------------------------------------------------------

# 8. Execution Guarantees

## NOT guaranteed:

-   ordering
-   exactly-once execution
-   deterministic routing
-   no duplication under failure

## PROVIDED:

-   best-effort execution
-   bounded propagation via TTL
-   capacity-aware routing
